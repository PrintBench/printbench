# Getting help with PrintBench

Start with the [documentation](https://docs.printbench.app), especially
[deployment](https://docs.printbench.app/deploy/),
[troubleshooting](https://docs.printbench.app/deploy/troubleshooting) and
[upgrading](https://docs.printbench.app/deploy/upgrading).

For a question that the docs do not answer, search the
[issue tracker](https://github.com/PrintBench/printbench/issues) first, then
open a **Help / question** issue. Include your PrintBench version, deployment
method, what you tried and relevant redacted logs. Questions and answers stay
public so other operators can find them. The project is maintained in spare
time; support has no guaranteed response time.

Use **Bug report** for broken behaviour and **Feature request** for a proposed
improvement. A request is not a commitment to implement it.

Never post credentials, access tokens, private model files or full `.env` files.
For vulnerabilities, use the private route in [SECURITY.md](SECURITY.md).
For unacceptable behaviour, use the private contact in the
[Code of Conduct](CODE_OF_CONDUCT.md).
