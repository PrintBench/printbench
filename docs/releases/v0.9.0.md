# PrintBench v0.9.0

## Highlights

- Manage and rotate shared S3 credentials in **Admin → Storage**. Multiple
  libraries can use one connection with different prefixes. The library list
  shows where each library lives and names the S3 provider. (#113)
- Edit a library's name and sidecar settings. An S3 library can switch to another
  connection to the same bucket. The **Add library** wizard keeps **Back** and
  **Cancel** in the same place on every step. (#113, #115)
- When removing an uploads library, keep its files, delete them after reviewing
  the preview, or move its indexed models to another uploads library. Moved
  models keep their IDs, notes, tags, print history and share links. Libraries
  that index existing files continue to offer only **Keep the files**. (#116)
- The development S3 Compose profile now uses SeaweedFS. The local endpoint and
  test credentials stay the same, and the verifier creates its test bucket when
  needed. (#114)

## Upgrade notes

- Back up your database and data before upgrading. Startup applies forward-only
  migrations 0021 through 0024. Each existing S3 library gets its own connection,
  and the migration carries over its encrypted credentials. Keep the existing
  `BETTER_AUTH_SECRET` during the upgrade. Existing portable backups migrate
  their S3 credentials when restored through PrintBench.
- Review **Admin → Storage** if you want multiple libraries to use one connection.
  New connections check access at the bucket root, so credentials restricted to a
  single prefix can fail validation. Existing S3 libraries keep their bucket
  and prefix.
- **Keep the files** is the default removal option. **Delete the files** can
  delete unindexed files too. Review the preview before confirming. Nested
  libraries are left alone.
- Production environment variables and Compose settings can be kept. The
  development S3 profile uses a new volume. A previous MinIO development volume
  is not migrated automatically.
