# PrintBench v0.7.0

PrintBench 0.7.0 adds filament inventory, whole-instance backup and restore,
and expanded Diagnostics. It also shows background activity across the app
and the running version in the user menu.

## Highlights

- Track filament spools, remaining weight, storage locations, purchase costs,
  and low-stock levels. Log several spools on a print with total usage and
  estimated cost. Completed, partial, and failed prints deduct stock; edits
  and deletions adjust the ledger while preserving manual corrections.
- Download a whole-instance `.pbbackup` from Manage → Backup, optionally
  including uploaded files and stored credentials. Restore over an existing
  instance or directly from the first-run setup screen.
- Inspect an audit trail, application logs, and debug information in Diagnostics.
- Follow scans, imports, uploads, and thumbnail work from a shared activity panel.
- See the running application version in the user menu and diagnostic reports.
- Add Docker healthchecks for the worker and nginx, and update production and
  development dependencies.

## Upgrade notes

- Back up the database before upgrading. The normal deployment migration flow
  applies `0016_numerous_metal_master.sql` for filament inventory and
  `0017_diagnostics.sql` for audit events, application logs, and process status.
  Existing print records remain unlinked to spools until edited.
- Custom deployments must pass the same `BETTER_AUTH_SECRET` to the web and
  worker services. The supplied Compose configuration does this. Use the updated
  nginx configuration for the new `/api/backup/` routes.
- Whole-instance backups contain account data and password hashes. The archive
  as a whole is not encrypted; only optionally included stored credentials are
  protected by a passphrase. Keep backups private.
- Whole-instance restore replaces the target instance. Restore into the same or
  a newer PrintBench version; in-place libraries must retain their container paths.
  Thumbnails are regenerated and active sessions are not restored.
- Metadata exports from `scripts/backup.mts` now include filament inventory in
  format v2; existing v1 imports remain supported.
